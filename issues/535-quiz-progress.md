# #535 Не сохраняется прогресс по выполненным заданиям (quiz)

**Статус:** 🟢 свободна · **Issue:** https://github.com/mimi-net/miminet/issues/535 · 2026-10-06
**Сложность:** низкая или средняя · **Linux-бэкенд:** не нужен (логика во фронтовом Flask и PostgreSQL)

## Суть
Задание отмечено как выполненное, но после выполнения другого задания снова показывает `0/1`. По словам автора, проблема
воспроизводится начиная с 6-го задания.

## Гипотеза (по коду, не воспроизведено)
Последняя попытка выбирается так:
- [`dto.py:487`](https://github.com/mimi-net/miminet/blob/24c36f3/front/src/quiz/util/dto.py#L487): `current_user_sessions.order_by(QuizSession.finished_at.desc()).first()`
- [`dto.py:208`](https://github.com/mimi-net/miminet/blob/24c36f3/front/src/quiz/util/dto.py#L208) (`get_last_correct_question_count_by_section`): та же сортировка.

В **PostgreSQL** при `DESC` значения NULL идут **первыми**. Поэтому любая незавершённая сессия (`finished_at IS NULL`),
например начатая и брошенная, считается «последней», и прогресс становится 0. Кроме того, в `SectionDto` не фильтруется `is_deleted`.
Существующие тесты `front/tests/test_quiz_progress.py` проверяют только арифметику процентов через моки и этот случай не ловят.

## Что сделать
1. Воспроизвести локально: пройти задание, начать другое и не завершать его.
2. Исправить: `.order_by(QuizSession.finished_at.desc().nulls_last())` или фильтр `finished_at.isnot(None)`
   (надо решить, что показывать для незавершённой попытки), плюс фильтр `is_deleted`.
3. Тест на PostgreSQL или SQLite с одной завершённой и одной незавершённой сессией.

## Вопросы
- Почему «начиная с 6»? Возможно, с 6-го номера начинаются практические задания, у которых сессия завершается иначе.
  Это нужно проверить при воспроизведении.

## Оценка сложности фикса (проверено 2026-10-23)

**Вердикт: 🟡 СРЕДНЕ.** 3–6 часов. Сам код небольшой, но **нужно продуктовое решение мейнтейнера** и правка в двух местах.
Гипотеза из раздела выше подтвердилась **частично**: реальная причина глубже.

**Полный механизм (по коду + эксперимент на PostgreSQL, `experiments/exp_535.py`):**
1. Каждый клик «Начать» по разделу создаёт новую `QuizSession` (`quiz/facade/quiz_session_facade.py:208`, `start_session`).
2. Перед этим фронт вызывает `finishOldQuiz()` (`static/quiz/quiz_scripts.js:13,40`) → `PUT /quiz/session/finishold` →
   `finish_old_sessions` (`quiz_session_facade.py:273`), которая ставит `finished_at = now()` **всем** незавершённым сессиям пользователя
   **во всех разделах**, включая брошенные без единого ответа.
3. Прогресс берётся из «последней» сессии по `finished_at DESC` (`quiz/util/dto.py:487` и `:219`).

Результат эксперимента:
```
after solving task 7:            session 1 -> 1/1
task 7 reopened, not answered:   session 2 -> 0/1 | nulls_last: session 1 -> 1/1
after starting task 8:           session 2 -> 0/1 | nulls_last: session 2 -> 0/1 | best -> 1/1
```
То есть сценарий из issue («задание 7 сменится на 0/1 после выполнения другого задания») воспроизводится один в один, и
**`nulls_last()` его не лечит**: после `finish_old_sessions` брошенная сессия получает самый свежий `finished_at`.

**Варианты исправления (выбирает мейнтейнер):**
- **A. «Лучший результат»:** показывать максимум правильных ответов среди завершённых и не удалённых сессий. Проще всего, и для
  практических заданий логично («задание решено — значит решено»). Для контрольных (`is_exam`) это, возможно, не подходит.
- **B. «Последняя сессия, где был хоть один ответ»:** игнорировать пустые сессии (`SessionQuestion.is_correct IS NULL` у всех вопросов).
- **C.** Не закрывать в `finish_old_sessions` пустые сессии, а удалять их (`is_deleted = True`). Это меняет поведение для экзаменов,
  поэтому самый рискованный вариант.

**Что менять в любом варианте:**
- `quiz/util/dto.py:487` (`SectionDto`) и `:208-231` (`get_last_correct_question_count_by_section`) должны использовать **одну** функцию
  выбора. Сейчас логика расходится: одна ветка фильтрует `is_deleted`, другая нет.
- `.nulls_last()` добавить в любом случае: без него незавершённая сессия считается «последней» ещё до `finish_old`.
- Ссылка «Посмотреть последний результат» (`session_guid`) должна вести на ту же сессию, которую показывает счётчик.

**Тесты и окружение:** Linux не нужен. Тест нужен **на PostgreSQL**: в SQLite при `DESC` NULL идёт последним, поэтому баг там не
воспроизводится. Готовая основа для теста — сценарий из `exp_535.py`. Существующий `test_quiz_progress.py` использует моки и этот
случай не покрывает.

**Почему «начиная с 6»:** по коду объяснения нет. Скорее всего, просто первые задания пользователь не открывал повторно. На
фикс это не влияет.

**Перед началом:** написать в issue найденный механизм и спросить, какой вариант (A/B/C) нужен. Это само по себе ценный вклад.
