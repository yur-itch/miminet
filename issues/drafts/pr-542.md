Closes #542

## Проблема
Тест, созданный через админку, сохраняется без автора (`created_by_id = NULL`), после чего `/admin/test/` отдаёт 500 (`Error occurred while retrieving user nickname`).

## Причина
В формах `TestView` (и, как выяснилось, `AnswerView`) осталось поле отношения `created_by_user`. Flask-Admin записывает пустое значение этого поля в модель (`populate_obj`), и при flush SQLAlchemy синхронизирует NULL из отношения поверх `created_by_id`, выставленного в `on_model_change`. У `SectionView` и `QuestionView` это поле уже исключено, поэтому разделы и задания создаются нормально.

## Решение
- исключить `created_by_id` и `created_by_user` из форм `TestView` и `AnswerView`;
- `created_by_formatter` показывает «—» и пишет warning в лог вместо исключения, чтобы записи, **уже** сохранённые без автора, не роняли страницу списка.

## Проверка
Локальный стенд (Flask-Admin 2.0.1, PostgreSQL 18), создание через формы админки:

| | до | после |
|---|---|---|
| Test: `created_by_id` | NULL | id админа |
| `/admin/test/` | 500 | 200 |
| Answer: `created_by_id` | NULL | id админа |
| `/admin/answer/` | 500 | 200 |

Добавлен `front/tests/test_admin_author.py` (без браузера и БД, внесён в `front_coverage.yml`): без фикса 4 из 5 тестов падают.

## Существующие записи
Тесты и варианты, созданные через админку до исправления, остались без автора, в списке у них показывается «—». Автора им можно проставить запросом вида `UPDATE test SET created_by_id = <id> WHERE created_by_id IS NULL` (для вариантов то же с таблицей `answer`).
